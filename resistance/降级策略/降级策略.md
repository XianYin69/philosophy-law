# 降级策略

## 触发条件与动作

| 触发 | 降级动作 |
|---|---|
| T1 官方链接不可达 | 改引 T2 公版文本并注明「官方版本待复核」；不删条目，标 `verified: partial` |
| 条文号无法确证 | 只给要旨级描述 + `待核`，禁止编造编号 |
| 知识树该节点无卡 | 如实说明缺口 → 记入 `asset/index/coverage.md` 前沿 → 询问是否联网补卡 |
| 现状数据缺来源 | 只写规范层，事实层写「无可靠数据」，趋势判断降为 `存疑` |
| 用户要求个案意见 | 拒绝并转介执业律师，改提供学理框架 |
| 校验脚本自身报错 | 退回人工九项清单，并把错误写入过程链 |
| 上下文超限 | 按 [机制兜底](../机制兜底/机制兜底.md) 压缩，保留条目 `id` 而非全文 |

## 禁止的降级

- 禁止以「大致如此」替代 `待核`；
- 禁止删除约束或跳过审查节点来「通过」；
- 禁止用相近条文号冒充（差一条也是编造）。

## 恢复

降级交付须在条目上留 `degraded: <原因>`，条件具备后由计划任务复核回升 `verified`。
